# Долгая отрисовка Servo: TrimUI Smart Pro, 2026-10-15

## Подтверждённая причина

В исходном профиле приложения кадры «Алюминия» занимали до 4,34 с,
«Натрия» — до 2,58 с при достаточной доступной RAM. Дополнительные замеры
на границе GLES воспроизвели кадр 7,53 с: 6,40 с пришлись на измеренные
GL-вызовы, преимущественно `glDrawElementsInstanced`. Отдельные первые
вызовы занимали 0,5–1,2 с, последующие — единицы миллисекунд.

Причина воспроизводимых пауз — дорогая компиляция вариантов шейдеров в
LLVM JIT llvmpipe. Это подтверждается сокращением задержек при замене
предварительно оптимизированных GLSL-шейдеров WebRender исходными и при
отключении дорогих LLVM-проходов. Точные доли компиляции и ожиданий внутри
каждого GL-вызова не снимались отдельным CPU sampling profiler.

Mesa [реализует создание вариантов перед рисованием](https://chromium.googlesource.com/chromiumos/third_party/mesa/+/refs/heads/stabilize-13982.70.B-chromeos-amd/src/gallium/drivers/llvmpipe/lp_state_fs.c),
а [режим `nopt`](https://chromium.googlesource.com/chromiumos/third_party/mesa/+/refs/heads/stabilize-13982.70.B-chromeos-amd/src/gallium/auxiliary/gallivm/lp_bld_init.c)
пропускает LLVM-оптимизацию и выбирает минимальный уровень codegen.
Приведённые ссылки — исходники Mesa того поколения, а не доказательство
совпадения всех деталей с каждым поставляемым бинарником.

## Воспроизведение и предварительное сравнение

Устройство: aarch64, 997816 КиБ RAM; software Mesa 20.3.5, LLVM 11.0.1,
llvmpipe 128 bit, до четырёх raster workers. Игра и Zimlite закрыты.
Архив `wikipedia_ru_chemistry_maxi_2026-07.zim`, статья «Алюминий».
Viewport 640×351, тёмная тема, motion scale 1. Защита памяти обычная.

`servo-probe --scroll-duration 25s` посылает ±24 CSS px каждые 33 мс,
меняя направление каждые 60 команд; начало замера после первого кадра,
завершение с дополнительными 3 с приёма кадров. Этот сценарий включает
оставшуюся загрузку ресурсов и компиляцию при первых перемещениях.

В первых сериях использовался общий дисковый кэш Mesa. Их результаты
показывают наблюдавшиеся паузы, но смешивают влияние настроек и прогрева.

| Вариант | Кадров за 25 с | Средний FPS | Макс. интервал между кадрами |
| --- | ---: | ---: | ---: |
| Исходные настройки | 96 | 3,84 | 7617 мс |
| Только `GALLIVM_PERF=nopt` | 125 | 5,00 | 3777 мс |
| Исходные GLSL WebRender, обычный LLVM | 147 | 5,88 | 2135 мс |
| Исходные GLSL + `nopt` | 135 | 5,40 | 1311 мс |

Повтор исходной сборки с прогретым кэшем дал 165 кадров / 6,60 FPS
и максимальный интервал 1446 мс. Это подтверждает необходимость отдельно
сравнивать холодную компиляцию с одинаковыми условиями кэша.

На «Натрии» только `nopt` дал 142 кадра / 5,68 FPS и максимальный
интервал 1879 мс. Это другая статья; сравнивать её FPS с «Алюминием» нельзя.
Полный кадр «Алюминия» с исходными GLSL + `nopt` получен и визуально
осмотрен: текст, таблица, изображение и схема периодической таблицы видны.

Это отдельный probe без SDL-окна. Средний FPS и максимальный интервал
относятся к этому сценарию, не являются гарантией для любых страниц или
показателями полностью прогретой прокрутки. Настройка `nopt` выбирается
только в режиме «Скорость»: она сокращает первые задержки ценой возможного
снижения скорости исполнения готовых шейдеров.

## Сравнение без дискового кэша

Для обеих сборок задан `MESA_GLSL_CACHE_DISABLE=true` (имя переменной
подтверждено в поставляемом Mesa 20.3.5). Остальные условия те же.

| Вариант | Кадров за 25 с | Средний FPS | Макс. интервал |
| --- | ---: | ---: | ---: |
| Исходная установленная сборка | 66 | 2,64 | 6647 мс |
| Только быстрый JIT (`nopt`), прежние GLSL | 92 | 3,68 | 4530 мс |
| Только исходные GLSL, обычный LLVM | 51 | 2,04 | 7344 мс |
| Исходные GLSL + быстрый JIT | 98 | 3,92 | 3908 мс |

Максимальная пауза сократилась примерно на 41%, средний FPS вырос примерно
на 48%. Первые неполные кадры получены за 1609 и 1624 мс соответственно:
это не замер готовности всей статьи. В итоговой серии `paint` занимал до
3063 мс; память не вызвала фоллбек, доступно минимум 375108 КиБ,
helper HWM не выше 257968 КиБ. События `servo.paint.slow` подтверждают,
что итоговая пара probe/helper обрабатывает новый протокол отрисовки.

Большие паузы полностью не устранены. Прогрев кэша — отдельный существенный
фактор; предварительную цифру 7617 → 1311 мс нельзя считать чистым
эффектом патча. Показатели получены в отдельных запусках, без усреднения
по множеству повторов и без контроля температуры/частоты CPU.

## Изменения

- Отдельный патч Servo выбирает исходные шейдеры только для llvmpipe с
  быстрым JIT (`GALLIVM_PERF=nopt`). При обычном LLVM остаются прежние
  шейдеры: их замена без быстрого JIT не дала выигрыша в контрольной серии.
  Vendor checkout остаётся без изменений.
- Режим «Скорость» включает быстрый software JIT через launcher, сохраняя
  пользовательское переопределение `GALLIVM_PERF`.
- Опциональное профилирование GL-вызовов включается отдельным флагом.
- Внешний watchdog ограничивает отдельный вызов отрисовки 10 секундами,
  включая работу после первого кадра; затем стандартная очистка и фоллбек.

Эти изменения не устраняют отдельные старые ошибки ядра `buffer_head` и
не доказывают причину окончательного системного зависания из предыдущего
неполного журнала. Замеры также не охватывают зависания вне вызова `paint`.


## Установка и заключительный замер

Исправленные приложение, helper и launcher установлены на TrimUI 2026-10-15.
Проверены SHA-256 и загрузка зависимостей; предыдущие три файла сохранены с
суффиксом `.before-paint-20261015`. Профилирование PortMaster остаётся включено.

Штатный установленный launcher, быстрый JIT, прогретый кэш, «Алюминий»,
15 с прокрутки: 72 кадра / 4,80 FPS, максимальный интервал 1345 мс.
Это дополнительный замер работоспособности установленной пары, а не
сравнение с 25-секундными холодными сериями. Ручная проверка всего UI и
физического стика после этой установки не проводилась. Таймаут зависшего
драйвера реализован; принудительная имитация зависания не выполнялась.

Сборки Linux PC и ARM64 выполнены, helper сохраняет ABI GLIBC <= 2.30
для ARM64; линтер Go — 0 замечаний. Unit/integration tests не запускались.
