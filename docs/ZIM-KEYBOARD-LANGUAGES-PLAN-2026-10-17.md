# Экранная клавиатура по языкам ZIM

## Требование

Доступные языки клавиатуры: языки метаданных Language открытого архива плюс английский. Английский доступен всегда. Язык интерфейса приложения хранится отдельно от языка ввода. Документ описывает предлагаемую реализацию; код клавиатуры пока не добавлен.

## Данные архива

Добавить чтение libzim Archive::getMetadata("Language") через существующий C++/Go bridge. Новый контракт Reader предоставляет нормализованный список языков и исходное значение для диагностики. Учитывать отсутствие метаданных, ошибки чтения, ограничения размера значения, пустые и повторяющиеся элементы.

Обычный формат: ISO 639-3 коды, разделённые запятыми, например rus,eng. Для совместимости разбирать также старые/нестандартные разделители ; и пробелы и известные двухбуквенные алиасы. Нормализация выполняется по встроенной таблице соответствий, а не обрезанием кода до двух букв. Специальные значения und/mul не являются раскладками; для них нужен выбор языка пользователем. Имя файла не использовать как достоверный источник языка.

Сохранить порядок языков, добавить eng при его отсутствии. Начальное выделение: сохранённый язык этого архива, если он доступен; иначе первый известный язык из метаданных; иначе eng. Порядок метаданных используется как политика выбора по умолчанию, а не доказательство основного языка.

При отсутствии/ошибке метаданных открыть английскую клавиатуру и дать явно указать языки архива через настройку. Эти переопределения хранить для UUID архива; путь может измениться при переименовании файла. Активные настройки применять к текущему архиву, а не объединять языки всех открывавшихся ZIM.

## Реестр профилей ввода

Связать canonical language ID с доступными профилями, названием для пользователя, письменностью, раскладкой экранных клавиш, методом m17n/другим движком, зависимостями и необходимыми шрифтами.

Примеры: eng -> встроенная английская раскладка; rus -> ru-kbd (вариант ru-translit); kor -> ko-han2; hin -> hi-inscript/hi-itrans; zho -> zh-py; jpn -> ja-anthy + Anthy. Предпочитаемый профиль запоминать для языка, чтобы пользователь не выбирал его при каждом открытии архива.

Язык не определяет однозначно письменность или метод: китайский требует выбора варианта письма/метода; сербский может использовать кириллицу и латиницу. Эти параметры входят в профиль и меняются внутри выбранного языка. Все варианты IME не должны засорять основной переключатель языков.

Если язык объявлен в архиве, но нет рабочего профиля, показать его с понятным состоянием доступности, дать выбрать подходящий профиль вручную и записать проблему в лог. Наличие кода в списке не считается поддержкой: полноценный профиль должен включать ввод и корректное отображение. Для выпуска каждого поддерживаемого пакета нужны проверки реального ввода. Unicode-палитра допустима как резервный инструмент, но не заменяет полноценный ввод языка.

## Пользовательский интерфейс

В клавиатуре показывать текущий язык, например Русский, и кнопку переключения языка. Быстрое переключение L/R действует внутри открытой клавиатуры. Короткий список языков соответствует текущему архиву и всегда включает English. Для большого списка предусмотреть меню выбора. Имена языков показывать собственными названиями и/или переводом интерфейса, без флагов государств.

Основная область: запрос, preedit, кандидаты, сетка клавиш. Перед сменой метода завершать композицию через IME; подтверждённый запрос сохранять, разрешая смешанный ввод. Крестовина управляет фокусом клавиатуры/кандидатов; ввод не должен запускать навигацию по ссылкам статьи. Отправка поиска использует подтверждённый UTF-8 текст.

Чтение статьи не должно ждать подготовки клавиатуры. При открытии ZIM читаются только небольшие метаданные; двигатель ввода запускается при открытии поля ввода.

## Границы модулей и память

- internal/zim: чтение Language и идентификатора архива, без знаний об экранной клавиатуре.
- internal/textinput: нормализация языков, разрешение профилей, текстовый буфер, состояния композиции и кандидатов. Общие модели не зависят от SDL/m17n.
- native/input-host: адаптер m17n и модулей преобразования, отдельный процесс с ограниченным IPC.
- internal/ui: жизненный цикл клавиатуры, выбор языка, передача событий и отправка поиска.
- internal/renderer: рисование клавиатуры, кандидатов и текста с правильным shaping/RTL.

В дистрибутиве хранить базу правил m17n, английский ввод и предусмотренные языковые зависимости для офлайн-работы. В память загружать выбранный метод. Для японского включить/поставлять Anthy и словарные данные. Недостающие данные выявлять до использования профиля; автоматическая сетевая загрузка не должна быть условием ввода в офлайн-читалке.

Из-за глобального кеша разобранных методов m17n закрытие контекста не гарантирует возврат всей памяти. Перезапуск input-host при смене языка/метода гарантирует освобождение памяти прежнего движка. Задержку такого переключения измерить на handheld. При закрытии клавиатуры завершать worker; английский прямой ввод может работать в основном приложении.

Ограничивать длину ввода, размер IPC-сообщений и выдачу кандидатов текущей страницей. Отдельно проверить шрифты, RTL, составные символы, Backspace и преобразование индексов символов m17n в индексы UTF-8/графем редактора.

## Этапы

1. Метаданные и resolver: проверить доступные реальные архивы; случаи rus, rus,eng, zho,jpn, пустые/повторяющиеся/неизвестные коды и переопределения.
2. Консольный input-host: английский, русский, корейский, хинди, китайский, японский, арабский; точный UTF-8, композиция, кандидаты, удаление и многократная смена языка. Измерить RAM/время на handheld.
3. SDL клавиатура 640x480: языки текущего ZIM + English, разные профили, отображение сложных письменностей, управление джойстиком.
4. Подключить подтверждённый запрос к FTS: первая страница заголовков, асинхронный поиск, отмена запроса, отдельный жизненный цикл поискового worker.

## Примеры

- rus -> Русский / English; начальный язык Русский.
- jpn -> 日本語 / English; японский профиль использует Anthy.
- rus,zho -> Русский / 中文 / English; одновременно работает только выбранный метод.
- eng -> English.
- метаданные отсутствуют -> English и возможность указать языки архива.

## Уточнение управления и размера

Полная панель вместе с запросом и кандидатами занимает максимум 30% экрана:
при 640×480 это 144 пикселя снизу. Крестовина перемещает фокус,
кнопки стиков не используются. Start в открытом архиве вызывает поиск,
Start внутри поиска отправляет запрос. Select возвращает фокус в поле.
L/R меняют язык при открытой панели, вне панели листают результаты.
F3 вызывает экранную клавиатуру вручную, включая ПК с физической клавиатурой.

Автоматический показ разрешён только при фокусе поля ввода и отсутствии
физической клавиатуры. В Linux проверяются буквенные клавиши input-устройств;
кнопки консоли и Power не считаются полноценной клавиатурой.
`KIWIX_PHYSICAL_KEYBOARD=0/1` позволяет исправить определение в необычном окружении.
Физический ввод работает и без экранной панели. После отправки запроса панель
скрывается, фокус переходит к результатам, worker ввода завершается.

Сборка офлайн runtime: `make input-runtime-arm64` / `make input-runtime-amd64`.
Папка `input` должна лежать рядом с исполняемым файлом; альтернативный путь
задаётся `KIWIX_INPUT_RUNTIME_DIR`. Linux-дистрибутивы и PortMaster включают её
автоматически. Нативный runtime Windows пока не собирается этими целями.

Реестр профилей использует названия и ISO-коды iso-codes (LGPL-2.1+),
методы m17n-db 1.8.14 и несколько дополнительных латинских профилей.
Английский доступен без нативного runtime; неизвестный язык остаётся в списке
с явным сообщением о недоступности метода. Наличие Unicode-шрифта само по себе
не означает наличие способа ввода каждого языка мира.

## Результат реализации

Реестр содержит 95 языковых профилей; английский работает без внешнего IME.
На ПК проверен вывод `привет`, `한글`, `नमस्ते` (hi-itrans), `你好`,
`日本` с выбором кандидата, `سلام`. Отдельно проверен shaping строк
на латинице, кириллице, китайском, японском, арабском, хинди и корейском.
Это выборочная проверка, не доказательство корректности всех 95 профилей.

На TrimUI Smart Pro проверены ru-kbd и ja-anthy с реальным преобразованием
и кандидатами. VmRSS/VmHWM после короткого ввода: 5640 КБ для ru-kbd,
8320 КБ для ja-anthy. Это память отдельного worker, без SDL интерфейса
и шрифтов приложения; длительный ввод и другие методы могут требовать больше.
Проверка шла рядом с запущенной игрой, поэтому замеры задержек не приводятся.
Физическая клавиатура на устройстве не обнаружена: его input-устройства
не объявляют набор Q/A/Z/Enter/Space.

## Исправление поиска хинди и оформления

На архиве wikipedia_hi_mathematics_maxi_2026-07.zim libzim выдаёт предупреждение
`No stemming for language 'hi'` в stdout. Результаты поиска при этом корректны,
но предупреждение нарушало протокол worker. Протокол теперь использует отдельный
дескриптор; stdout библиотеки перенаправлен в stderr, диагностика ограничена
4096 байтами и попадает в лог приложения. Предупреждение означает отсутствие
стемминга, а не отсутствие поддержки поиска текста хинди.

Панель ограничена 640 пикселями по ширине и центрируется на большем экране.
Высота по-прежнему не больше 30% и максимум 144 пикселя. Координаты клавиш
и обработка нажатий учитывают смещение панели. Три позиции пробела объединены
визуально и при навигации крестовиной. Оформление использует текущую тему,
скругления, отдельное поле запроса, языковую плашку и контрастный фокус.

## Мобильная раскладка

Основная панель содержит Shift, язык и ?123, буквенные ряды со смещением,
Backspace справа, широкий пробел, запятую/точку и ввод. Выбор метода находится
в меню языка. Цифры и символы используют две страницы; Shift переключает
их, ABC возвращает буквы. Смена языка завершает композицию до открытия меню.

Раскладка описывается ключами с действием, физическим значением для IME,
подписью и положением. Английский использует ряды 10/9/7 букв; дополнительные
клавиши m17n, выдающие буквы/комбинируемые знаки, сохраняются для русского и
индийских раскладок. Меню языка показывает девять крупных пунктов на странице.
Крестовина движется по действительным клавишам; вертикальный переход выбирает
ближайший центр в соседнем непустом ряду. Широкий пробел является одной клавишей.
Shift, удаление и Enter рисуются векторами. Кнопка языка использует 🌐
(1f310.svg) из встроенного Twemoji через общий кеш эмодзи, без зависимости
от системных шрифтов.

## Поиск во время ввода и управление фокусом

Запрос обновляется через 350 мс после изменения текста, включая текущую
композицию без принудительного commit. Новое изменение отменяет старый FTS
запрос, его ответ не принимается. Пустой запрос очищает выдачу. Сам поиск
оставляет IME и клавиатуру активными; Enter/кнопка ввода подтверждает композицию
и переводит фокус к результатам. Стартовый запрос и смена страниц также остаются
асинхронными; лимит памяти worker продолжает действовать.

Start переключает ввод/результаты с сохранением запроса. A выбирает клавишу
или открывает статью. B при вводе удаляет символ, в меню языка закрывает меню,
в списке результатов возвращает к исходной статье. L1 удаляет символ; из
результатов сначала возвращает фокус вводу. Назначения подтверждения/назад
используют существующий маппинг приложения (SDL B/A соответственно).

Левый стик перемещает фокус в активной области с повторами по удержанию:
400 мс у границы deadzone и 85 мс при полном отклонении. Выбирается доминирующая
ось с гистерезисом 15%, чтобы диагональ не вызывала дрожание. Крестовина
сохраняет управление фокусом. Размер панели по-прежнему до 640×144; панель
поднята над строкой статуса, результаты используют оставшийся viewport.
Подсказка статуса зависит от фокуса и наличия геймпада и переведена на 13 языков.
