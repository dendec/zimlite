# Оценка m17n для клавиатуры zimlite

Проверены официальные исходники m17n-lib 1.8.6 и m17n-db 1.8.14, а также документация Input Method (basic). Исследование исходников; библиотека не собиралась, замеры RSS на handheld не выполнялись.

## Вывод

m17n подходит как основной движок правил ввода и композиции для SDL-клавиатуры. Готовой гарантии удобного ввода на всех языках он не даёт. Покрытие определяется установленными методами, таблицами символов, внешними модулями, шрифтами, отображением и интерфейсом клавиатуры.

В MIM каталоге m17n-db 1.8.14 найдено 212 файлов .mim, суммарно 2 545 712 байт (2,43 МиБ), 70 разных негeneric языковых идентификаторов в объявлениях input-method. Это не 212 независимых пользовательских методов и не точное число поддерживаемых языков: есть вспомогательные файлы, языковые группы и общие методы для латиницы/символов. Размер исходных таблиц не равен памяти после разбора.

## Покрытие

- Кириллица: ru-kbd, ru-translit, ru-phonetic, ru-yawerty; имеются украинские и белорусские методы.
- Латиница и диакритика: прямой ввод и общие latn-pre/latn-post. Для многих языков нет необходимости иметь отдельный IME.
- Арабский/персидский/иврит, армянский/грузинский: представлены методы ввода. Отображение и направление текста проверяются отдельно.
- Индийские письменности: множество InScript, ITRANS, фонетических и других методов, например девять hi-*.mim для разных схем хинди в этой версии.
- Корейский: ko-han2 и ko-romaja составляют хангыль; для базового хангыль-ввода отдельная libhangul не обязательна.
- Китайский: zh-py, zh-tonepy, zh-zhuyin, zh-cangjie и другие табличные методы. В zh-py основная таблица сопоставляет слоги отдельным символам-кандидатам. Полноценная современная конверсия фраз и контекстное предсказание не следуют из наличия этой таблицы. Покрытие редких и новых иероглифов требует проверки.
- Важно: zh-pinyin вводит латинскую запись пиньиня с тонами, а не иероглифы. Для иероглифов выбирается другой метод, например zh-py.
- Японский: ja-anthy использует внешний модуль libmimx-anthy.so и Anthy для преобразования каны в кандзи. Одного m17n-db для этого пути недостаточно. ja-tcode/ja-trycode — другие, специализированные методы; они не равнозначны привычному вводу ромадзи с преобразованием фраз.
- Произвольный Unicode: ввод кодовой точки и таблица символов пригодны как резервный путь. Это не обеспечивает удобный повседневный ввод на неизвестном языке. Наличие unicode.mim также не заменяет проверку всего допустимого диапазона Unicode.

## Интеграция с SDL и геймпадом

Для внутренних методов достаточно basic/shell API: m17n-core + libm17n; m17n-shell.pc.in не требует m17n-gui. Передача условных клавиш, preedit, подтверждённого текста и кандидатов доступна приложению. Экранные окна IBus/Fcitx/X11 не обязательны для такого использования. Внешние методы имеют собственные зависимости.

Поток: экранная кнопка -> символ клавиши m17n -> minput_filter -> при необходимости minput_lookup -> обновление UTF-8 редактора, preedit и кандидатов. Для части методов нужны callbacks получения и удаления окружающего текста. Их нельзя опускать, если требуется широкое покрытие.

Файлы .mim описывают правила и состояния, а не универсальную машинную модель сетки экранных кнопок. ru-kbd содержит обычное отображение q->й и текстовое описание раскладки; другие методы используют состояния, комбинации клавиш и внешние модули. Автоматическое построение удобной экранной клавиатуры из произвольного .mim отдельная задача. Практичный старт: общая латинская сетка для транслитерации и отдельные описания кнопок/слоёв для прямых раскладок.

Ввод и отображение проверяются отдельно. Для текста поиска и preedit нужны шрифты с нужными глифами, shaping, двунаправленный текст и редактирование по графемам. Наличие метода ввода само по себе не меняет отрисовку SDL.

## Память

Малый размер таблиц делает m17n хорошим кандидатом для 1 ГБ RAM, но фактическое потребление ещё не измерено. Следует отдельно проверять простые схемы, китайские таблицы и Anthy.

В src/input.c есть глобальный im_info_list. open_im получает описание метода из этого списка. Внутренний close_im только обнуляет im->info; список разбираемых методов очищается в minput__fini. Поэтому закрытие контекста не доказывает немедленное освобождение всех таблиц языка. Нужен профиль при многократном переключении методов и проверка корректного завершения жизненного цикла библиотеки. Отдельный процесс клавиатуры даёт простой способ гарантированного освобождения памяти.

## Следующий прототип

Консольный адаптер до разработки экранного интерфейса: ru-kbd, ru-translit, ko-han2, hi-itrans, vi-telex, ar-kbd, zh-py и ja-anthy с Anthy. Проверять точный UTF-8 результат, preedit, выбор кандидатов, Backspace, окружающий текст, переключение языка, задержку и RSS. Отрисовку сочетаний и RTL затем проверять в реальном SDL поле на 640x480.
